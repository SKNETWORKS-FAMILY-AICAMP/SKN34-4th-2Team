요청 단위 검색 임베딩 묶음 및 중복 조회 제거 — 2026-10-10

변경
- 동일 요청의 고유 검색문을 embed_documents 한 번으로 처리하고 정책·공지 벡터 검색에 공유한다.
- 검색문, 검색 namespace, 기수 필터, 검색 건수와 정책 원문 연결은 유지한다.
- 캐시는 요청 객체에만 존재하며 사용자·기수·다음 질문 간 공유하지 않는다.
- 병렬 검색에서 최초 배치 실패 시 다른 namespace가 같은 배치를 반복 호출하지 않는다.
- student_private/cohort_shared/study_room은 질의 문구와 무관한 현재 DB 스냅샷이므로 같은 요청에서 성공적으로 조회한 scope를 다시 읽지 않는다.
- 파일 검색은 질문별 관련도가 달라지므로 기존의 개별 질의를 유지한다.
- embedding_calls는 검색 횟수 대신 실제 embedding 배치 실행 횟수를 기록한다. SDK 내부 재시도·대형 입력 분할의 과금 집계는 아니다.

검증
- 관련 오프라인 테스트 67개 통과. 병렬 배치, 실패 재호출 방지, 요청 간 격리, 검색 범위·필터 보존, 개인 조회 중복 제거 포함.
- 별도 허용된 테스트 계정 두 개에서 실제 답변 검증. SDK 경계에서 재시도를 끄고 전체 호출 상한 9회를 적용했으며 실제 사용은 6회.
- 두 계정 모두 이전과 같은 계산값 및 기수별 기준을 안내했다.
- 정책·공지 검색 임베딩은 각각 요청당 1회로 감소했다.

시간 해석
- 4기 동일 질문: 이전 24.390초, 변경 후 37.187초.
- 3기 동일 질문: 이전 39.235초, 변경 후 36.747초. 과거 측정과 비교이며 동시 A/B 실험이 아니다.
- 전체 지연 감소는 입증되지 않았다. 모델 판단에 따라 검색 횟수·scope도 달라져 측정 조건이 완전히 같지 않다.
- 변경 후 학생 컨텍스트 조회는 14.061초 / 14.862초, 답변 입력은 약 69,000자였다.
- 확인된 효과는 검색 임베딩 중복 비용 절감이다. 다음 우선순위는 개인·기수 조회의 세분화 및 답변에 필요한 데이터만 전달하는 설계다.
- 평균·백분위나 속도 개선율로 발표하지 않는다. 원본 응답 및 시간 기록은 로컬 작업 output/hybrid-local-site/latency-batch-results.json에 보관한다.
