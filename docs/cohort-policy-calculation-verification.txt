기수 업로드 정책과 개인 출결 계산 연결 — 2026-10-10

구현 범위
- 정책 업로드 시 기존 조 단위 파서와 기준 추출기로 수료·장려금·결석 환산 후보를 추출한다.
- 업로드별 고유 Pinecone namespace 첫 청크에 기준 스냅샷을 저장한다.
- 색인 확인 후 활성화하는 기존 DB 포인터를 개인 계산에서도 사용한다.
- 개인 계산은 활성 파일을 S3에서 읽고 동일 추출기로 해석한다. 파일 키별 메모리 캐시를 사용하므로 정책 교체 시 새 키를 읽는다.
- 기수의 내부 숫자 ID로 호출되는 개인 기록 조회도 DB에서 확인한 기수 코드로 정책을 조회한다.
- 기준 미확인·중복·충돌 시 공통 JSON 80%/3회로 대체하지 않는다. 원본 출결과 수업일 정보는 제공한다.
- 규정 검색은 같은 활성 파일의 Pinecone namespace를 사용한다. 계산 조회 후 정책이 바뀌면 재질문하도록 중단한다.
- 관리자 업로드 결과에 기준 누락 경고를 표시한다. 일부 목적의 기준 누락이 다른 목적의 유효한 기준을 무조건 막지는 않는다.

지원 및 제한
- 현재는 정비된 규정집 DOCX 조문과 기존 추출기가 지원하는 문구를 대상으로 한다.
- 임의 PDF 또는 다른 표현의 숫자를 무조건 자동 계산 기준으로 채택하지 않는다.
- 수료는 전체 훈련기간, 장려금은 단위기간으로 분리한다. 계산은 서버 코드, 숫자 기준은 해당 기수 문서에서 가져온다.
- 정책의 검토 상태는 unverified이다. 업로드 성공이 공식 승인 또는 지급·수료 확정을 의미하지 않는다.
- 적용일·개정 이력의 자동 판정은 포함하지 않는다. 과거 단위기간 확정 판정은 숨기고, 전체 수료 비교는 현재 활성 정책을 적용한 예상값으로 표시한다.
- 단위기간 달력 생성과 실제 수업 일정은 별개이다. 기존 월별 기간 생성 방식은 유지하며 일정의 검토 상태도 유지한다.
- 운영진이 기준을 확인하고 승인하는 별도 관리 기능은 아직 없다.

검증
- 계산·검색·문서 회귀 테스트 62개 통과 후, 숫자 기수 ID 회귀 테스트 1개 추가; 해당 모듈 8개 통과.
- Django 업로드 테스트 13개 통과. 실제 DOCX 파싱 → 업로드 핸들러 → 활성 파일 읽기 → 계산 검증 포함. 외부 저장은 mock 처리.
- 관리자 문서 화면 테스트 5개 통과, TypeScript tsc -b 통과.
- 사용자가 별도로 허용한 격리 테스트 기수 2개에서 실제 S3 업로드와 Pinecone 색인, 학생별 기준 조회 및 답변 확인.
- 기존 운영 학생·기수의 정책과 출결은 수정하지 않았다. 테스트 계정 비밀번호·원본 출결·실제 답변 기록은 저장소에 포함하지 않는다.
- 초기 실제 답변 검증에서 개인 조회가 내부 기수 ID를 전달하는 문제를 발견하고 코드 정규화 및 회귀 테스트로 수정했다.
- 수정 후 두 기수의 답변 생성 전체 시간은 39.235초, 46.867초. 기능 검증 결과이며 성능 평균이나 백분위가 아니다.
- 실행 결과와 테스트 로그인 정보는 로컬 작업 output/hybrid-local-site에만 보관한다.

API 테스트 집계 주의
- 최초 HTTP 계층 계수기가 실제 SDK 실행 경로를 포착하지 못했다. 0회 출력은 실제 사용량이 아니다.
- 초기 실행은 업로드 임베딩 2회 + 두 문항의 supervisor/answer 각 1회 및 embedding 각 2회로 10회였다.
- 사용자의 추가 최대 8회 승인 후 수정 검증 두 문항을 실행했다. 각 문항의 supervisor/answer 및 embedding 2회가 기록되어 예상 합계 8회이다.
- HTTP 계수기는 재시도까지 보장하는 감사 장치로 검증되지 않았으므로 재사용하지 않는다. 추후 자동 평가 전 SDK 호출 경계에서 차단하는 장치가 필요하다.
