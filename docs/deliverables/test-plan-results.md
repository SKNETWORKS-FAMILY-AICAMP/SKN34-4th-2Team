## 1. 테스트 개요

### 1.1 테스트 기간

기록된 선별 검증일은 2026-10-13이다. 이 보고서는 기존 실행 기록을 정리하며 추가 테스트를 실행하지 않는다. 10월 14일 일정은 산출물 확인·발표 준비 계획이다.

### 1.2 테스트 대상

React 웹, Django API, FastAPI AI, Expo 앱으로 구성한 LXP 2.0이다. 기록된 실행 범위는 정책 문서 청킹, 코드 튜터 규칙, 기술명 정규화 및 일부 React 기능이다.

### 1.3 테스트 목표

요구사항의 권한·기수 격리, 근거 보존, 단계별 학습 지원, 선택 적용, 운영 기록 내보내기를 확인한다. 코드 구현 여부와 운영 통합 검증을 구분한다.

### 2. 테스트 목적

정책 문서의 조문·조건·예외 보존, 튜터 답안 노출 제한, 첨삭 상태 전환, 복습 기록 및 내보내기 데이터의 회귀를 확인한다. 실제 LLM의 답변 품질과 클라우드 통합은 별도 검증 범위로 관리한다.

## 3. 테스트 환경

### 3.1 하드웨어 환경

기존 기록은 로컬 Windows 작업 환경의 결과이다. CPU·RAM과 실제 모바일 기기 정보는 해당 기록에 없어 기재하지 않는다. 운영 서버 부하 검증 결과로 해석하지 않는다.

### 3.2 소프트웨어 환경

기준 커밋은 5f4f005이며 당시 develop 작업 트리에서 실행했다. Python 가상환경의 unittest와 React 프로젝트의 Vitest를 사용했다. 최신 커밋의 재실행 결과는 아니다.

### 3.3 네트워크 환경

튜터 LLM 호출은 대체했다. 해당 선별 실행은 실제 OpenAI·Pinecone·RDS·S3·Redis와 AWS 배포·HTTPS를 검증하지 않는다.

### 3.4 테스트 도구 및 소프트웨어

Python unittest, React Vitest를 사용했다. 첨삭 적용 Python 테스트는 pytest 부재로 수집 전에 중단했다. 전체 테스트와 웹 빌드는 실행하지 않았다.

## 4. 테스트 케이스

### 4.1 모델링 평가 계획

학생 챗봇은 기수 일치·근거 인용·문서 밖 질문 거절을, 추천은 조건 충족·마감·인용 원문 일치를, 첨삭은 사실 보존·선택 적용을 평가한다. 실제 모델의 정량 점수는 이번 선별 기록에 없어 산출하지 않는다.

### 4.2 기능 테스트 결과

정책 문서 적재 16개, 코드 튜터 11개, 기술명 정규화 5개가 통과했다. React 첨삭 세션 44개, 복습 기록 12개, 튜터 화면 5개, 표 내보내기 4개가 통과했다. 총 97개는 선택한 단위·화면 테스트에 한정한다.

### 4.3 성능 테스트 계획

학생 챗봇 최초 표시 지연·전체 응답 시간, 추천 단계별 시간, 첨삭 단계 재개 및 동시 요청을 같은 입력·환경으로 측정한다. 목표 시간과 동시 사용자 수는 운영 기준 확정 후 정한다. 이 선별 검증에는 성능 측정값이 없다.

## 4.2 통합 테스트 시나리오 - 계획

### TC-01 ~ TC-04 인증·학생 챗봇

TC-01: 역할·기수·소유권 밖 조회를 차단한다. TC-02: 기수별 정책 업로드 후 해당 기수로 답한다. TC-03: 이미지 공지에서 추출한 내용을 검색한다. TC-04: 잘못된 정책 파일 업로드 시 기존 활성 문서를 유지한다. 통합 실행 상태는 미실행이다.

### TC-05 ~ TC-08 학습·취업

TC-05: 노트를 재사용하고 복습 이력을 저장한다. TC-06: 튜터 대화·단계별 힌트를 유지한다. TC-07: 후속 질문의 공고 검색 조건을 유지한다. TC-08: 이력서에 없는 사실 추가를 보류한다. 통합 실행 상태는 미실행이다.

### TC-09 ~ TC-12 적용·운영

TC-09: 선택 적용·되돌리기에서 버전 충돌을 확인한다. TC-10: 관리자 확인 전 알림을 발송하지 않는다. TC-11: 파일의 범위·건수가 선택한 운영 기록과 일치한다. TC-12: 예약 공지·첨삭 작업 중복 실행을 제한한다. 통합 실행 상태는 미실행이다.

## 5. 과거 이력 관리

### 2026-10-13 / 5f4f005 / Python

정책 청킹·튜터·기술명 정규화 32개 통과이다. unittest 실행 기록을 보존한다.

### 2026-10-13 / 5f4f005 / React

첫 실행은 EPERM으로 수집하지 못했다. 파일 접근을 허용한 동일 범위의 재실행에서 4개 파일 65개 테스트가 통과했다.

### 2026-10-13 / 첨삭 Python 적용 테스트

pytest가 없어 수집 전 중단했다. 성공 또는 실패로 집계하지 않는다.

### 후속 변경 관리

새 실행 시 커밋·날짜·명령·환경·결과·실패 원인을 별도 검증 기록에 남긴다. 기존 결과를 최신 코드 전체 통과로 갱신하지 않는다.

## 6. 테스트 결과 및 결론

### 6.1 통과 결과 요약

기존 기록의 Python 32개와 React 65개 통과를 확인했다. 전체 서비스 통과율과 모델 정확도는 계산하지 않는다.

### 6.2 잔존 후속 작업

첨삭 Python 적용 테스트, Django DB 통합, 역할별 E2E, 실제 LLM·클라우드 연동, AWS 배포, Expo 실기기 검증이 남아 있다. GitHub #17·#33과 연계해 범위별 결과를 기록한다.

### 6.3 결론

정책 청킹·튜터 규칙 및 선택한 화면 로직의 회귀 근거를 확보했다. 기록되지 않은 통합·운영 동작은 미검증으로 유지한다.
