답변 스트리밍 및 출결 조회 연결 절감 — 2026-10-10

변경
- 답변 모델의 stream을 명시적으로 소비하고 텍스트 조각만 LangGraph custom 이벤트로 전달한다.
- supervisor 구조화 출력과 reasoning 블록은 사용자 스트림에 포함하지 않는다.
- 마지막까지 합친 답변을 기존 대화 이력과 사용량 계측에 저장한다.
- 빈 응답은 한 번만 안내하고, 중간 생성 오류는 상위 NDJSON 오류 처리로 전달한다.
- Django 줄 단위 중계와 React NDJSON 표시는 기존 구현을 유지한다.
- 출결 전용 scope는 자체 로더가 수행하는 기수·사용자 조회를 바깥 로더에서 반복하지 않는다.
- 정책·출결·검색 범위와 계산 로직은 유지한다.

검증
- 전체 chatbot 테스트 126개 통과.
- 모델이 완료되지 않은 상태에서 첫 답변 조각을 수신하는지 이벤트로 동기화해 검증했다.
- reasoning 미노출, 중간 오류, 단일 fallback, 최종 합성 답변과 토큰 사용량 보존 검증.
- 실제 테스트 두 문항에서 기수별 정책과 추가 출석 필요일 유지.

실측 (단일 실행의 AI NDJSON 생성 구간; 브라우저 첫 페인트 측정 아님)
3기: 첫 텍스트 20.087초, 완료 23.917초, 텍스트 조각 192개, 개인 조회 3.984초.
4기: 첫 텍스트 18.968초, 완료 22.972초, 텍스트 조각 200개, 개인 조회 4.535초.
직전 개인 조회는 각각 5.891초, 6.646초였다.
전체 완료 속도가 항상 개선됐다는 근거는 아니다. 완료 전 텍스트 전달과 중복 연결 제거를 확인한 결과다.
초기 기수 일정 로딩 및 브라우저 네트워크/렌더링은 위 시간에 포함되지 않는다.

계측 유의
custom 모드에서 supervisor의 구조화 호출은 Responses.parse 경로를 사용할 수 있다.
create/embeddings만 감싼 테스트 계수기 출력 4회는 전체 호출 수가 아니다.
별도로 수행된 supervisor 2회가 있으며, 후속 API 평가 계수기는 parse 경로까지 포함해야 한다.
재실행이나 추가 모델 테스트는 하지 않았다.

상세 로그는 로컬 output/hybrid-local-site/latency-stream-results.json에 보관하며 Git에는 개인 답변을 포함하지 않는다.
