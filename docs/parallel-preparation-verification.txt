Why the previous smaller prompt was sometimes slower
- Prior three-pair answer-stage test: mean first text 5.519 -> 6.655 seconds,
  after-first-text generation 1.735 -> 1.568 seconds.
- Reasoning output tokens summed 1283 -> 1602; visible output 674 -> 651.
- Largest difference: missing-record case reasoning 478 -> 848 and first text
  6.055 -> 8.809 seconds. Context builder/DB time was outside that timer.
- These observations locate the delay before first text, not in output length
  or the context-building CPU work. They do not prove references caused it;
  server latency, prompt cache and model reasoning variability are confounders.
- One further frozen missing-record pair reversed the time ordering:
  legacy 9.017 seconds / TTFT 6.806 / reasoning 516;
  compact 8.487 seconds / TTFT 6.689 / reasoning 362.
  Provider input remained 7753 -> 6960; both were predominantly cache hits.
  Both answers retained 13 recorded/12 recognized, 92.3 percent and refused a
  definite future normal-attendance requirement without the missing record.
- Keep compact opt-in; no conclusion of general speed gain or regression.

Implementation by Sol; review and testing by primary
- LMS_CHATBOT_PARALLEL_PREP=1 enables only chat endpoints; default OFF.
- Common schedule loader and supervisor overlap because supervisor consumes
  message history, not the common schedule. Join before downstream nodes.
- /init keeps its prior contract; direct explicit common context remains valid.
- Loader is an injected dependency; UID/cohort and the single-worker executor
  are request-local. No future/executor is stored in graph state/checkpoints.
- Supervisor failure drains the worker and preserves the supervisor exception.
  Shared-load errors use the previous unavailable-context response.
- Missing context/session fields explicitly clear prior graph-state values.
- No threshold, calculation, retrieval, routing prompt or answer prompt changes.
- New metrics: shared_context_ms, supervisor_prepare_wall_ms,
  shared_context_overlap_ms and parallel_prep_enabled. supervisor_ms measures
  supervisor only. Node wall time excludes eager API work in serial mode;
  compare from BEFORE _chat_inputs for a fair preparation measurement.

Rollout and rollback
- Existing serial mode stays default. Local/staging opt-in first; unset the flag
  to return to the serial path. Compact remains legacy by default independently.
- Reject rollout for any calculation/source/cohort isolation regression, added
  errors, or worse latency under representative repeated/concurrent traffic.
- One additional worker per in-flight chat may affect capacity; four-session
  isolation tests do not substitute for representative concurrency/load testing.
