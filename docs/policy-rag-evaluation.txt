정책 RAG 변경 비교 평가
2026-10-09 / 평가 과정의 운영 데이터 변경 없음

배포 상태 정정: 구조 청킹/참조 조회 코드는 별도 배포 이미지에 이미 포함된 것으로 확인됐다.
아래 평가는 운영 활성 문서 포인터를 변경하지 않았으며, 배포 승인 근거로 사용하지 않았다.
세부 배포 추적은 docs/policy-rag-delivery.txt를 참고한다.

[후속 실행 상태]
사용자가 외부 전송을 승인하고 질문 수를 20개로 축소하여 1회 비교를 실행했다.
실행 입력: chatbot/evaluation/policy_rag_cases_20.json (40개 원본 질문 풀은 유지).
임베딩 API 2개 배치, 자동 재시도 0회, LLM 답변 생성 0회.
16개 답변형 질문의 전체 근거 확보는 A/B/C 모두 14/16. 나머지 4개는 답변 검토가 필요하다.
이번 작은 표본에서 개선/회귀는 없었으며 B/C의 평균 본문 분량은 약 22.3% 늘었다.
이하 외부 승인 차단 기록은 승인 전 최초 시도의 기록이다. 추가 실행은 별도 횟수 승인이 필요하다.

1. 목적과 현재 상태
검색 코드 회귀 테스트와 실제 답변 품질 검증은 구분한다.
평가 도구와 질문 40개를 작성했고, 오프라인 동작 검사를 실행했다.
질문은 34/40기 각각 20개(답변 가능한 규정 질문 18개, 문서에 없는 질문 1개,
개인 기록이 필요한 질문 1개)다. 답변 질문 36개의 모든 정답 인용문을 원본 DOCX와 대조했다.
정답 세트는 운영진 승인 전 평가 초안이며 법률/운영 규정의 정확성을 인증하지 않는다.
동일 질문을 기수별로 반복하므로 40개가 서로 독립적인 다양한 질문 40종을 뜻하지 않는다.

외부 임베딩 평가 실행은 자동 승인 검토에서 차단됐다. 이유: 문서 원문과 평가 질문을
OpenAI로 전송하는 데 대한 명시적 사용자 승인이 필요하다는 판정이다.
해당 호출은 실행되지 않았다. 임베딩/모델 답변 품질 및 비용 결과는 아직 없다.
오프라인 문자 유사도 검사 수치를 운영 검색의 정확도로 해석하지 않는다.

2. 비교 조건
A: 같은 규정 DOCX 본문에 기존 split_body 500자/40자 겹침 방식을 적용.
B: 같은 규정 DOCX의 조 전체 청크.
C: B와 같은 검색 + 실제 expand_policy_context 함수의 한 단계 참조 확장.
세 방식 모두 같은 장/조 제목, 같은 기수 원문, 같은 질문, 같은 k=4를 사용한다.
A는 이전 정책집과 운영 색인을 그대로 재현한 것이 아니라, 청킹 효과를 분리하는 대조군이다.
최종 전환 전에는 실제 운영 기준과의 종단 비교를 추가한다.
현재 파서가 기수별 44조를 보존하며 전체 원문 byte hash를 기록한다.
manifest에 질문 파일 hash, 실행 코드 hash, 모델/차원/설정도 기록한다.

3. 평가 항목
article_recall: 필요한 조문 중 검색한 비율.
all_required_articles: 필요한 조문을 모두 찾았는지 여부.
evidence_recall: 정답에 필요한 원문 인용문이 실제 같은 기수·조문의 검색 텍스트에 포함된 비율.
all_evidence: 필요한 모든 원문 인용문 확보 여부.
cross_cohort_count: 다른 기수 텍스트 혼입 수. 오기수 결과는 정답률에 가산하지 않는다.
paired_comparisons: 평균이 개선돼도 개별 질문에서 퇴보한 경우를 목록화한다.
context_chars: 모델에 줄 본문 분량. 실제 모델 토큰 비용과 같지 않다.
문서에 없는 질문/개인 기록 질문은 근거 검색 점수를 N/A로 두고, 답변의 절제 여부를 별도 검토한다.
인용문이 여러 청크에 걸쳐 있을 때 각 청크 안의 완전한 인용문 포함을 기준으로 측정하므로 보수적이다.
이 점수는 답변의 정답률이 아니다.

4. 실행 도구
chatbot/evaluation/evaluate_policy_rag.py
chatbot/evaluation/policy_rag_cases.json
chatbot/tests/test_policy_rag_evaluation.py

실행 예시 (저장소 루트에서 Python 환경 활성화 후):
python -m chatbot.evaluation.evaluate_policy_rag --document "cohort_34=<34기 DOCX 경로>" --document "cohort_40=<40기 DOCX 경로>" --cases chatbot/evaluation/policy_rag_cases.json --output "<새 결과 폴더>" --mode prepare

prepare: 원문·정답 인용 검증, A/B/C 청크와 manifest 생성. 외부 호출 없음.
lexical: 문자 bigram 유사도 기반 오프라인 동작 검사. BM25도 운영 임베딩 검색도 아니다.
embedding: OpenAI로 청크/질문을 보내 임베딩 후 로컬 exact cosine 검색.
           모델 기본값 text-embedding-3-small, 차원 기본값 1536.
           Pinecone 호출이나 운영 DB/S3 수정은 하지 않는다.
           모델/차원/텍스트 hash별 로컬 캐시로 B/C 및 중복 텍스트 임베딩을 재사용한다.
--answers --answer-model <모델명>: 명시적으로 선택할 때만 추가 OpenAI 답변 생성.
           모든 방식에 동일 프롬프트/모델/최대 출력 예산을 사용한다.
           실제 호출의 토큰 사용량과 모델 응답시간을 저장한다.
           비용 금액은 계정 가격 확인 전 자동으로 추정하지 않는다.
--embedding-cache <경로>: 이전 평가의 임베딩 캐시 재사용.
결과 폴더에 manifest가 있으면 덮어쓰지 않는다. 실패한 실행의 부분 결과도 보존한다.

5. 결과 파일
manifest.json: 입력/모델/설정/실행 식별.
corpus-<기수>-<방식>.json: 실제 평가한 청크.
results.json: 질문별 검색 원문·점수·근거 회수율; 선택 실행한 경우 모델 답변/토큰.
summary.json: 방식별 집계 및 질문별 개선/퇴보 목록.
blind-review.json: 방식 이름을 감춘 답변/근거 검토용 파일.
blind-review-key.json: 방식 매핑. 검토 완료 전 리뷰어에게 제공하지 않는다.
답변 생성을 실행하지 않은 경우 blind-review의 answer는 null이며 답변 평가 완료를 뜻하지 않는다.
검토자는 정답 여부, 조건/예외 누락, 근거 적합성, 답변 보류 적절성을 기록한다.

6. 운영 전환 기준과 복구 준비
도구는 자동 운영 전환을 하지 않으며 모든 실험 결과는 검토 대기 상태다.
- 기수 혼입, 개인 결과 추정, 근거 없는 확답 등 중대한 오류가 있으면 전환하지 않는다.
- 평균 개선만 보지 말고 이전 방식 대비 퇴보한 모든 질문을 검토한다.
- C가 B보다 근거 회수에 도움이 없으면 참조 확장을 운영 전환 근거로 삼지 않는다.
- 모델 답변 블라인드 비교와 추가 사용자 질문 검증을 완료한다.
- 실제 서비스의 동시 요청 조건에서 p50/p95 응답시간, fetch 호출, 토큰 비용을 비교한다.
- 허용할 응답시간/비용 상한은 사용자와 합의 후 운영 승인 기준으로 확정한다.
- 기존 운영 색인/문서 연결과 실행 이미지 정보를 보존하고, 테스트 환경에서 복구 절차를 검증한다.
현재 평가 도구에는 운영 플래그 전환·복구 자동화가 포함되어 있지 않다.

7. 로컬 검증
python -m unittest chatbot.tests.test_policy_rag_evaluation -v
평가 전용 테스트 9개: 동일 원문/재현성, 정답 drift, 중복 질문, 기수 격리,
조문 적중과 실제 문장 확보 구분, N/A 처리, 실제 참조 확장 연결,
외부 호출 없는 prepare/lexical, 질문별 회귀 검출을 확인한다.
운영 검색·계산 로직은 이번 평가 도구 작업에서 수정하지 않았다.
