로그인 후 학생 챗봇 준비 배치 — 2026-10-12 KST

범위
최신 코드 이미지의 AI 호스트에 별도 chat-cache Redis를 선택적으로 배치합니다.
Django 호스트의 인증·Celery Redis와 일반 REDIS_URL 설정은 변경하지 않습니다.
로그인/세션 복원 후 서버 백그라운드 준비 흐름을 유지합니다.
챗봇 창 열기를 준비 트리거로 바꾸거나 브라우저 데이터를 캐시 근거로 쓰지 않습니다.
이 문서는 배포 절차이며 이번 작업에서 운영 배포·환경변수 변경은 수행하지 않았습니다.

AI 전용 캐시 URL
CHATBOT_CONTEXT_REDIS_URL → REDIS_URL → redis://127.0.0.1:6379/0 순서입니다.
빈 값 또는 공백만 있는 값은 다음 설정으로 넘어갑니다.
이 우선순위는 chatbot/context_cache.py에만 적용됩니다.
URL·자격증명을 로그에 출력하지 마세요. 연결 설정 변경 후 AI 프로세스를 재생성해야 합니다.

Opt-in overlay
기존 deploy/docker-compose.ai.yml과 deploy/docker-compose.chat-cache.yml을 함께 사용합니다.
같은 Compose project 이름으로 실행해야 기존 ai 서비스와 동일 네트워크에 연결됩니다.
overlay 없이 실행하는 기존 배포는 변경되지 않습니다.

저장소 루트에서 승인된 배포 시 사용하는 명령:

  docker compose --env-file .env -f deploy/docker-compose.ai.yml -f deploy/docker-compose.chat-cache.yml config --quiet
  docker compose --env-file .env -f deploy/docker-compose.ai.yml -f deploy/docker-compose.chat-cache.yml up -d chat-cache ai

ECR_AI_IMAGE에는 이번 코드가 포함된 이미지를 지정해야 합니다.
처음에는 LMS_CHATBOT_WARMUP을 설정하지 않거나 0으로 두어 기능 OFF 상태로 확인합니다.
AI 전용 URL은 overlay가 redis://chat-cache:6379/0으로 지정합니다.

자원·접근 경계
Redis 7, maxmemory 128 MiB, 컨테이너 한도 256 MiB, noeviction입니다.
호스트 포트·데이터 volume을 게시하지 않으며 AOF/RDB 저장도 비활성화합니다.
protected-mode는 AI의 컨테이너 간 접속을 위해 비활성화했습니다.
따라서 호스트 포트를 추가하거나 비신뢰 컨테이너를 같은 네트워크에 연결하지 마세요.
healthcheck는 상태 확인용이며 ai에 service_healthy 의존성을 걸지 않습니다.
캐시 장애·메모리 부족으로 읽기/쓰기가 실패해도 원본 조회와 backoff가 유지됩니다.
TTL 300초·항목 128 KiB 상한·DB 권한/버전 확인은 유지합니다.

양쪽 서버 활성화
1. 최신 코드의 Django와 AI 이미지, AI chat-cache PING 및 내부 통신을 먼저 확인합니다.
2. AI 호스트 배포 환경에 LMS_CHATBOT_WARMUP=1을 설정하고 ai를 재생성합니다.
3. Django의 CHATBOT_URL이 AI 내부 주소를 가리키고 LMS_AI_SHARED_TOKEN이 양쪽에서
   일치하는지 서버에서 확인합니다. 비밀값을 화면·문서·로그에 노출하지 마세요.
4. Django api 환경에도 LMS_CHATBOT_WARMUP=1을 설정하고 해당 서비스를 재생성합니다.
   Django에 AI 캐시 주소를 REDIS_URL로 넣지 않습니다.
5. 로그인 응답이 준비 완료를 기다리지 않는지, worker 간 재사용·사용자 격리·데이터 변경·
   캐시 만료/재시작/장애 fallback을 검증한 뒤 활성 상태를 유지합니다.

롤백
양쪽 서버 LMS_CHATBOT_WARMUP=0 적용 후 해당 프로세스를 재생성하면 원본 조회로 복귀합니다.
필요하면 AI overlay 구성을 유지한 채 chat-cache 서비스만 stop할 수 있습니다.
overlay를 제거할 경우에도 같은 project의 ai를 기본 compose로 다시 재생성합니다.
전체 compose down, 인증 Redis 제거, FLUSH는 필요하지 않습니다.
캐시는 재생성 가능하므로 컨테이너 재시작 후 사라진 항목은 miss로 처리됩니다.
배포/롤백은 별도 운영 승인에 따라 수행하며 이 문서의 명령은 자동 실행되지 않습니다.
