3. 앞으로의 배포 원칙
작업 단위별 커밋 → 원격 작업 브랜치 푸시 → 검토/통합할 커밋 확정 → 그 커밋의 깨끗한 checkout에서 빌드.
다른 작업의 미커밋 변경이 남은 현재 폴더를 그대로 배포 빌드 컨텍스트로 사용하지 않는다.
현재 폴더에 변경이 남아 있으면 임의 삭제/스태시하지 말고, 확정 커밋의 별도 checkout을 사용한다.
빌드할 때 전체 Git SHA와 이미지 digest를 함께 기록하고, 배포 상태는 실행 이미지에서 확인한다.
이 문서는 작업 원칙이며 기존 배포 도구에 자동 차단 기능을 추가한 것은 아니다.

4. 검증 이력과 제한
구조 청킹/업로드 관련 테스트 57개, 평가 도구 테스트 9개를 이전 단계에서 통과했다.
승인된 검색 비교 1회: 질문 20개 × A/B/C 3방식. 실제 임베딩 API 2배치, 자동 재시도 없음.
답변형 16개에서 전체 근거 확보는 각 방식 14/16. 평균만으로 품질 개선을 주장하지 않는다.
supervisor 호출은 별도 승인된 총 2회만 실행했다. 이후 제안한 추가 2회는 실행하지 않았다.
커밋 정리 단계에서는 새 테스트/API 평가를 실행하지 않는다. 실행 횟수는 사용자 승인을 먼저 받는다.
로컬 문서 경로·결과 파일은 환경별로 달라질 수 있으며 원본 DOCX와 임베딩 캐시는 Git에 포함하지 않는다.
